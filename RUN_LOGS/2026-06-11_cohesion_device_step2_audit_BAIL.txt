Step 2 — retire per-step pose pull: FEASIBILITY AUDIT -> BAIL (no flip). For the planner.

demandSyncPoseToHost still fires 1/step on contractilityAssay_gpu (calls=10203; gated on the
noMonomersSimd:false flag). After Step 1 (cohesion on device), the cohesion FORCE no longer reads
host pose. But the pose pull CANNOT be retired yet — remaining per-step host-pose consumers:

1. updateMyosinDimerPositions() (MyoMiniFilament.updateMyosins, myoJoints2 wave) — reads the body's
   host pose via xToX to recompute the world dimer attach points (myoDimerPtsEnd*InX). These are now
   DEAD: the device dimerCohesionKernel computes the attach point internally (body.coord +
   offsetX·body.uVec), and the CPU constrainEnd*Dimers that consumed them is gated off. So this is a
   dead per-step host-pose read. GATEABLE (skip updateMyosinDimerPositions when the body's dimers are
   cohesionOnDevice) — a small clean follow-on, not done here to keep Step 1 isolated.
2. refreshMiniFilBodyDerived() (Phase A) — refreshes the body's host transXTox/end1/end2 after the
   pull, solely to feed updateMyosinDimerPositions's xToX. Retires WITH (1).
3. The contractility anchor pin (applyBenchmarkPins) — reads host getEnd1/2 every step to snap the
   pinned plus-ends. Assay-harness only (absent in production minifilament configs), but on THIS
   config it is a genuine per-step host-pose read that blocks the flip.
4. Biochem (FilSegment.biochemStep) — gated on !noMonomersSimd, so the pull stays on by the flag.
   Turnover is zeroed here so biochem doesn't fire, but the gate is conservative; a real biochem-active
   minifilament config keeps the pull (the next-session event-cadence work).

ALSO NEW (from Step 1's workaround): the body-reaction host bridge reads cohBodyForce/cohBodyTorque
(device->host) EVERY_EXECUTION. This is a FORCE readback, not a pose read, so it does not block the
pose-pull retirement — but it means the body cohesion is not fully residency-clean (a per-step
device->host transfer remains). A working device-side body gather (the task that wouldn't execute,
see step1 log) would remove it.

VERDICT: cohesion is NOT the last per-step host-pose consumer (contrary to the prior session's Step-3
audit, which predated this port and didn't account for updateMyosinDimerPositions or the anchor pin).
DO NOT flip. To retire the pull on contractilityAssay_gpu: (a) gate updateMyosinDimerPositions +
refreshMiniFilBodyDerived off under cohesionOnDevice (quick), (b) move the anchor-pin end read off the
host or accept it as harness-only and flip on a pin-free production minifilament config, (c) the
biochem event-cadence sync remains the separate next-session item. The body-reaction device gather
(unblocking the host bridge) is the other open thread.
