THE FIX
-------
Forces C (MyoMiniFilament.constrainEnd1/2Dimers) and D (MyosinDimer.applyRodCoupling*)
read myoRod.end1AsPt3D()/end2AsPt3D() == soaEnd1/End2. On the GPU path those derived
fields are refreshed only at output cadence (and the -3js readonly fix restores them to
pre-output values), so per-step they are FROZEN while soaCoord/soaUVec are demand-synced
fresh every step (biochem configs, !noMonomersSimd). Replaced those reads with rod ends
DERIVED on-the-fly from fresh pose: end1 = coord - 0.5*length*uVec, end2 = coord +
0.5*length*uVec, via new Thing.freshEnd1AsPt3D()/freshEnd2AsPt3D(). Same formula
recomputeDerivedSoA / fillSoaArrays use; no new transfer, no per-step derived-SoA
recompute. On the CPU path coord/uVec are also fresh and soaEnd1 == coord-half*uVec, so
freshEnd == end1AsPt3D bit-for-bit — no CPU behavioral change.

Force B (keepMyosinsOnSurface) was ALSO switched to freshEnd for safety, but is inactive
in this fixture (numMyosinHeads==0; the 32 myosins are dimer-organised, so only C and D
apply). E (alignUVecLeversTorque) already read fresh uVec — left as-is.

CONFIRMED before coding: demandSyncPoseToHost() runs every step when !noMonomersSimd
(GPUMoveThing.java:5363), pulling device coord/uVec -> host soaCoord/soaUVec; soaEnd1/End2
are NOT in that pull. boa10-singleMiniFil is noMonomersSimd:false -> coord/uVec fresh.
Loop order (BoxOfActin.doLoop): myoJoints1/2 (cohesion) -> gatherForces -> GPU pack+integrate.
So the rod's +F cohesion force IS gathered and packed to device before integration; both
halves of each action/reaction pair are applied. No mistimed-pack bug.

SPIN METRIC  (scripts/spin_metric.py)
-------------------------------------
Per myosin, signed rotation of its rod center about the minifilament (bundle) axis,
frame to frame: dtheta = atan2((p_f x p_{f+1}).ahat, p_f . p_{f+1}), p = perp component
of (rodCenter - bundleCenter). cloud coherence = |sum mean_dtheta| / sum |mean_dtheta|
(1 = ballistic/coherent spin, 0 = diffusive). 63 frames (~300 steps), seeds 7 & 11.
Matched before/after (pre-fix built from parent 00f324b in-tree via git stash).

  config              net rotation (deg)   cloud coherence   per-myo mean coherence
  PRE-FIX GPU s7          +148.8               0.662              0.245
  POST-FIX GPU s7          +90.7               0.273              0.169
  CPU s7 (post-fix)         +7.5               0.031              0.138
  PRE-FIX GPU s11          +95.5               0.670              0.290
  POST-FIX GPU s11         -61.8               0.455              0.111

(On-disk pre-fix survey frame _s7 scored cloud coherence 0.675 with this metric, matching
the survey's reported 0.65 for seed 7 — metric calibrated. The survey's headline 0.98 was

VERDICT: the fresh-geometry fix REDUCES the coherent spin substantially (0.66 -> 0.27/0.46;
~40-60% of the per-frame rotational bias removed) but does NOT bring it to CPU's diffusive
0.03-0.07. A residual coherent rotation (~1.5 deg/frame consistent bias) remains.

WHY THE RESIDUAL IS NOT STALE GEOMETRY
--------------------------------------
Post-fix GPU geometry at the cohesion phase is now as fresh as CPU (both read end-of-
previous-step pose). The per-step derived-SoA recompute (the residency retreat we avoided)
would produce the SAME coord+/-half*uVec ends freshEnd already computes -> it cannot reduce
the residual further. So the residual is NOT a stale-geometry effect and does NOT warrant
the recompute (no hard bail).

on the float64 CPU-integrated minifil body do not cancel exactly in rotation, leaving a small
systematic tangential bias. This is a rotational generalisation of survey clue 2 (the
two-integrator seam) -- a further seam, FLAGGED for jba, NOT fixed in Phase 2a.
